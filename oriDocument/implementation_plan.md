# 心理健康教育咨询中心助理排班管理系统实施计划

## 1. 实施目标

本计划用于指导 AI 开发者将现有移动端 HTML 原型迁移并实现为微信原生小程序 + 自建后端 + MySQL 的完整本地可测试全栈系统，并在保持 `DESIGN.md` 与现有 HTML 页面视觉风格的基础上，完整覆盖 `design_document.md` 与 `tech_stack.md` 中定义的业务、技术、权限、状态流转、数据对象和质量要求。

最终技术路线为：微信原生小程序前端、Node.js Express TypeScript 后端、本地 MySQL 数据库、后期腾讯云服务器部署、后期腾讯云 COS 文件存储。开发期优先完成本地闭环：微信开发者工具运行小程序，前端请求本地 Express 后端，后端读写 `localhost:3306` 的 MySQL 数据库，数据库名暂定为 `psych_scheduler`。

正式登录最终使用微信 `openid`。测试阶段暂不实现真实 `openid` 登录，先实现临时身份分流页，提供 1 个管理员测试入口和多个助理测试入口。该测试入口只允许开发环境使用，正式接入微信登录后必须删除。

## 2. 全局约束

1. 所有实现必须优先参考 `oriDocument/DESIGN.md`、现有 HTML 原型页面和 `tech_stack.md`，不得重新发明一套视觉语言。

3. 所有敏感业务规则必须由 Express 后端校验，前端只做展示、输入收集和交互反馈。

AI 开发者指令：检查项目根目录，识别此前 CloudBase 路线产生的文件或目录。若存在与新路线冲突的 CloudBase 配置、云函数目录或占位文件，先向用户说明并在获得明确许可后清理。随后建立 `miniprogram`、`server`、`sql` 三个主目录。

### 步骤 2.2：初始化微信原生小程序前端

AI 开发者指令：在 `miniprogram` 中创建微信原生小程序 TypeScript 工程最小骨架，准备全局应用状态、API 基础地址配置和临时测试身份入口页面。不要实现真实业务页面。

AI 开发者指令：在 `server` 中创建 Node.js Express TypeScript 工程，建立应用入口、路由入口、统一错误处理、环境配置读取、健康检查接口和开发启动脚本。

AI 开发者指令：在 `server` 中建立 `.env.example`，按 `localhost:3306` 和数据库名 `psych_scheduler` 给出配置模板。建立数据库连接模块，所有连接信息从 `.env` 读取。

### 步骤 2.5：建立 SQL 脚本组织方式

AI 开发者指令：在 `sql` 中建立建表脚本、种子数据脚本和迁移记录目录，明确顺序编号、重复执行策略、迁移记录规则和基础建表/种子执行方式。此步骤只负责 SQL 目录组织方式、基础建表和种子执行方式，不要求在此阶段重复细化后续所有字段设计。

验证测试：空数据库执行 SQL 脚本后能生成基础表；重复执行应有明确策略，不能静默产生重复脏数据；种子数据能创建测试管理员和多个测试助理。

AI 开发者指令：检查收集数据、排班数据、日程展示、换班结果、加班统计、导出文件和分享页面是否基于同一数据源或一致快照。

验证测试：同一周期中，排班结果页、日程页、分享页、图片和 Excel 的班次人员一致；排班调整后旧导出文件不应被误认为最新结果；页面应提示重新导出。

## 19. 阶段十七：正式 openid 登录

### 步骤 17.1：收集微信登录所需信息

AI 开发者指令：在准备正式登录前，向用户确认小程序 AppID、AppSecret、后端 HTTPS 域名和微信公众平台 request 合法域名配置。

验证测试：缺少任一信息不得实现正式登录；AppSecret 不得写入前端或文档；合法域名配置必须能被微信开发者工具或真机请求访问。

### 步骤 17.2：实现 openid 登录 API

AI 开发者指令：小程序调用 `wx.login()` 获取 code，后端使用 AppID 和 AppSecret 换取 openid，并根据 openid 查询 users 表完成身份识别。

验证测试：已绑定 openid 用户进入对应角色；未绑定 openid 用户进入待登记或联系管理员状态；后端不向前端返回 AppSecret；微信接口失败时有明确错误。

### 步骤 17.3：移除测试分流入口

AI 开发者指令：正式 openid 登录通过后，删除或禁用测试分流页和测试登录 API，保留必要的开发测试脚本但不得暴露给生产环境。

验证测试：生产环境无法通过测试身份进入系统；正式用户只能通过微信登录进入；权限穿透测试仍通过。

## 20. 阶段十八：腾讯云部署与 COS

### 步骤 18.1：准备腾讯云服务器部署信息

AI 开发者指令：部署前向用户确认腾讯云服务器公网 IP、操作系统、登录方式、安全组端口、生产域名、HTTPS 证书、Nginx 策略、PM2 策略、生产 MySQL 账号和密码。

验证测试：信息不完整不得部署；服务器安全组只开放必要端口；生产 `.env` 不进入仓库。

### 步骤 18.2：部署 Express 后端和 MySQL

AI 开发者指令：在腾讯云服务器安装 Node.js、MySQL、PM2 和 Nginx，创建生产数据库，执行 SQL 脚本，部署后端服务。

验证测试：HTTPS 健康检查可访问；后端能连接生产 MySQL；PM2 重启后服务恢复；Nginx 反向代理正常。

### 步骤 18.3：接入腾讯云 COS

AI 开发者指令：配置 COS Bucket、地域和服务端访问密钥。Excel 导出上传到 COS，并在 `exported_files` 表记录 COS key 和访问地址。

验证测试：管理员导出后文件上传 COS 成功；助理不能导出；旧导出版本可追溯；COS 密钥只存在服务端。

### 步骤 18.4：执行云端验收

AI 开发者指令：在生产类环境执行主流程、权限、导出、通知和 openid 登录验收。

验证测试：小程序真机可通过合法域名访问后端；openid 登录可用；生产数据库不被本地测试污染；Excel 导出文件可下载；权限穿透测试通过。

## 21. 推荐开发顺序
